# Vue 3 watch computed watchEffect

## 🟢 问答 1：Vue 中 `watch` 和 `computed` 的核心区别是什么？

### 💡 核心对决表

| 特性       | `computed` (计算属性)         | `watch` (侦听器)            |
|:---------|:--------------------------|:-------------------------|
| **核心定位** | 减少模板内的繁琐运算，**派生新状态**      | 响应数据的变化，**执行特定业务逻辑**     |
| **缓存机制** | **有缓存**。只有依赖项改变时才会重新计算    | **无缓存**。只要监听的值变了就一定会执行回调 |
| **异步操作** | **不支持异步**。无法在异步任务中返回结果    | **支持异步**。适合网络请求、定时器等操作   |
| **返回值**  | **必须有返回值**（通常通过 `return`） | **不需要返回值**               |
| **依赖关系** | 一个值受多个值影响（多对一）            | 一个值的变化引发多个操作（一对多）        |

### 🛠️ 最佳场景 Demo

* **`computed` 最佳用例**：多对一。例如购物车结算（依赖单价、数量、优惠券，派生出总价）。
* **`watch` 最佳用例**：一对多/副作用。例如搜索框（输入框 `keyword` 变了，触发异步 API 请求获取搜索建议）。

## 🟢 问答 2：为什么说 computed 不支持异步？无法在异步任务中返回结果？

在 `computed` 中尝试使用异步操作（如 `fetch`、`setTimeout`）是典型的反模式，原因有两个层面：

### 1. 语法限制：无法通过 `return` 拿到异步结果

`computed` 本质上是一个同步执行的函数，Vue 需要立刻拿到返回值来渲染界面。

```javascript
// ❌ 错误代码示范：无法拿到异步结果
const userProfile = computed(() => {
    let result = '';

    // 这是一个异步操作
    fetch('/api/user').then(res => res.json()).then(data => {
        result = data.name; // 3. 很久之后才执行，但此时 computed 已经结束了
    });

    return result; // 1. 瞬间就执行了，此时 result 还是空字符串 ''
});
```

* **结果**：页面永远拿不到异步请求回来的完整数据。即使你强行 `return fetch(...)`，组件模板最终收到的也是一个
  `[object Promise]`，页面无法直接渲染。

### 2. 机制限制：异步代码会破坏 Vue 的“依赖追踪”

Vue 的依赖收集是同步的。当 `computed` 开始运行时，Vue 会开启一个“监听雷达”。一旦同步代码执行完毕，Vue 就会关闭雷达。

```javascript
// ❌ 错误代码示范：依赖丢失
const myValue = computed(() => {
    // 1. 同步代码开始，Vue 开启雷达

    setTimeout(() => {
        // 3. 异步回调执行。此时 Vue 的雷达早就关闭了！
        // 即使这里读取了响应式变量 `state.age`，Vue 也无法捕捉到它。
        console.log(state.age);
    }, 1000);

    return 'hello'; // 2. 同步代码结束，返回 'hello'，Vue 关闭雷达
});
```

* **后果**：由于 `state.age` 是在异步回调中被读取的，Vue 无法把它记录为依赖。后续哪怕 `state.age` 改变了，这个 `computed` 也
  **绝对不会重新触发计算**。

## 🟢 问答 3：在 computed 里，我直接用 async/await 不行吗？

**依然不行**。原因同样是 JavaScript 语法和 Vue 依赖追踪的双重锁死：

### 1. `async` 会强行让函数返回 Promise

在 JavaScript 中，任何标记了 `async` 的函数，其返回值都会被自动包装成一个 Promise 对象。

```javascript
// ❌ 错误示范：computed 变成了异步函数
const userInfo = computed(async () => {
    const res = await fetch('/api/user');
    const data = await res.json();
    return data.name;
});
```

对于 Vue 来说，它收到的 `userInfo.value` 是一个状态为 Pending 的 `Promise`。Vue 模板无法在页面上渲染一个 Promise
对象，你的页面上最终只会显示：

```html

<div>[object Promise]</div>
```

### 2. `await` 会直接斩断 Vue 的依赖追踪

当代码执行到 `await` 这一行时，整个函数的同步流会**当场暂停并退出**，Vue 会立即关闭“监听雷达”。**在 `await`
之后出现的变量，将无法被自动收集。**

```javascript
const count = ref(0);

const doubleCount = computed(async () => {
    // await 之前：Vue 还能看得见
    await someAsyncFunction();

    // await 之后：Vue 已经关闭雷达了！
    return count.value * 2; // ❌ 即使 count 改变，整个 computed 也再也不会重新执行
});
```

## 🟢 问答 4：既然 computed 玩不转异步，那 watchEffect 是什么？

`watchEffect` 是 Vue 3 引入的**自动侦听副作用函数**。它就像是 `watch`
的“智能自动挡”，不需要你手动指定监听谁，它会自动分析代码，只要在大括号里用到的响应式数据变了，它就会自动重新执行。

### 🛠️ 优雅平替 Demo：用 watchEffect 实现“异步计算属性”

回到想直接 `await` 的诉求，在原生 Vue 3 中，最优雅的平替方案就是用 **`ref` + `watchEffect`**：

```javascript
import {ref, watchEffect} from 'vue';

const userId = ref(1);
const userName = ref('加载中...'); // 1. 先定义一个用来渲染页面的响应式变量

// 2. 直接在 watchEffect 里写 async/await
watchEffect(async () => {
    // 3. 🟢 await 之前读取：userId 成功被收集为触发器！只要它变了，整个副作用重新跑
    const res = await fetch(`/api/user/${userId.value}`);
    const data = await res.json();

    // 4. 异步请求完成后，把结果喂给响应式变量，从而驱动界面更新
    userName.value = data.name;
});
```

## 🟢 问答 5：watchEffect 和 watch 到底有什么区别？

核心区别在于：**`watch` 是“精确的手动挡”，必须明确指定监听谁；`watchEffect` 是“智能的自动挡”，会自动追踪代码里用到的所有响应式数据。
**

### 💡 机制对比表

| 特性             | `watch` (手动挡)                              | `watchEffect` (自动挡)               |
|:---------------|:-------------------------------------------|:----------------------------------|
| **依赖显式声明**     | **必须手动指定**监听源（如 `watch(count, ...)`）       | **无需指定**，自动收集函数内用到的响应式数据          |
| **首次执行时机**     | **默认是惰性的**，只有数据变了才执行（除非配 `immediate`）      | **组件初始化时会立即执行一次**，用于收集依赖          |
| **获取新旧值**      | **可以**同时拿到新值 (`newValue`) 和旧值 (`oldValue`) | **无法**拿到旧值，只能获取当前最新值              |
| **异步对依赖收集的影响** | 没影响，因为依赖是手动在第一个参数里写死的                      | **有影响**。`await` 之后读取的变量无法被自动收集为依赖 |

### 🛠️ 关键坑点 Demo：异步对依赖收集的影响

* **`watch` 免疫异步影响**：因为监听目标在第一个参数定死了。
  ```javascript
  watch(userId, async () => {
    await someAsyncProps();
    console.log(count.value); // 🟢 安全。哪怕在 await 之后，count 变了也不会干扰 watch，只有 userId 能触发它。
  });
  ```
* **`watchEffect` 会被 `await` 拦截雷达**：
  ```javascript
  watchEffect(async () => {
    console.log(userId.value); // 🟢 await 之前，userId 被成功监听
    await fetch('/api');       // 🛑 暂停！Vue 雷达关闭
    console.log(page.value);   // ❌ await 之后，page 无法被监听！即使 page 改变，watchEffect 也不会重新触发
  });
  ```

## 🟢 问答 6：那这样看，watchEffect 是不是可以完美替代 computed？

**绝对不行**。`watchEffect` 无法完美替代 `computed`。`computed` 拥有一个 `watchEffect` 无论如何都无法做到的核心大招：**缓存机制
**。

### 🛠️ 性能大比拼 Demo：复杂长列表过滤

假设我们有一个包含 10,000 条数据的商品列表，我们要过滤出高评分的商品。

* **使用 `computed`（🟢 高性能推荐）：**
  具有 **`dirty`（脏数据）标记机制**。只要依赖项没变，多次调用直接在内存中秒回结果。
  ```javascript
  const expensiveFilter = computed(() => {
    console.log('正在执行上万条数据的复杂过滤...'); // 无论模板中复制多少次，这里雷打不动只打印 1 次！
    return hugeList.value.filter(item => item.score > 9);
  });
  ```
  在模板中渲染时：
  ```html
  <div>{{ expensiveFilter }}</div>
  <div>{{ expensiveFilter }}</div> <!-- 🟢 直接读取缓存，不跑函数 -->
  <div>{{ expensiveFilter }}</div> <!-- 🟢 直接读取缓存，不跑函数 -->
  ```

* **尝试用 `watchEffect` 强行替代（❌ 潜在性能灾难）：**
  没有缓存机制。只要被触发，或者组件更新引发重新渲染，它都必须硬生生地把这 10,000 条数据重新循环过滤一遍。
  ```javascript
  const filteredList = ref([]);
  watchEffect(() => {
    console.log('正在执行上万条数据的复杂过滤...'); // 只要数据一变，或者触发重绘，它就会反复从头到尾执行
    filteredList.value = hugeList.value.filter(item => item.score > 9);
  });
  ```

### 🛠️ 代码繁琐度对比 Demo：派生一个姓名

* **`computed` 声明式（一步到位）**：
  ```javascript
  const fullName = computed(() => firstName.value + lastName.value);
  ```
* **`watchEffect` 命令式（繁琐）**：
  ```javascript
  const fullName = ref(''); // 必须多定义一个变量
  watchEffect(() => {
    fullName.value = firstName.value + lastName.value; // 必须手动赋值，污染外部变量
  });
  ```

## 我的理解
`watchEffect` 作用和 `computed` 很相似，用于监听多个变量的变化，但是 `computed` 有缓存机制，性能比较好。
`watch` 适合监听单个/多个变量的变化，相比于 `watchEffect` 它支持获取旧值（oldValue）。`watchEffect` 会在定义的时候初始化一次，watch 则不会
