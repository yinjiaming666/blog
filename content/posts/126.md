# Redis 事务

[参考](https://www.cnblogs.com/gange111/p/19075653)

## 基本命令

### Redis 事务的本质是将多个命令打包，然后按顺序、一次性、隔离地执行。它通过 MULTI, EXEC, DISCARD, WATCH 四个核心命令实现。

- MULTI：开启一个事务，之后的命令都会放入队列，而不是立即执行。
- EXEC：执行事务队列中的所有命令。
- DISCARD：取消事务，清空队列。
- WATCH：在 MULTI 之前，监视一个或多个 key。如果在 EXEC 执行前，这些被监视的 key 被其他客户端修改，则整个事务会失败（EXEC 返回
  nil）。这是实现乐观锁（Optimistic Locking） 的基础。

## 注意

- 不保证原子性（Atomicity）：Redis 事务保证的是隔离性（Isolation） 和顺序执行，但不保证原子性。这意味着如果事务中某个命令执行失败（例如对字符串执行了
  HINCRBY），其他命令依然会继续执行，且不会回滚（Rollback）
- 执行成功 仅表示命令入队并执行，不保证已持久化到磁盘（需配合 AOF 配置 appendfsync always 提升可靠性，但会牺牲性能）。

## WATCH 实现乐观锁

```shell
127.0.0.1:6379> WATCH money # 如果在 `WATCH` 字段后，这个字段被其他客户端修改，则 `EXEC` 会返回 `nil`。
 OK
127.0.0.1:6379> MULTI
 OK
127.0.0.1:6379(TX)> INCR money
 QUEUED
127.0.0.1:6379(TX)> EXEC
  1) (integer) 2
```
