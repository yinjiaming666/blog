MySQL ON DUPLICATE KEY UPDATE 用法

作用：存在更新不存在插入(upsert)。性能一般会比先 select 后 update/insert 要好

1. 触发条件

只有以下约束发生冲突时，才会执行 ON DUPLICATE KEY UPDATE：

  • 主键（PRIMARY KEY）
  • 唯一索引（UNIQUE KEY），包括联合唯一索引

普通索引（INDEX / KEY）不会触发更新。

2. 联合唯一索引

以房间等级进度表为例：

CREATE TABLE s_room_level_progress (
    id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,
    owner_uid BIGINT UNSIGNED NOT NULL,
    room_id BIGINT UNSIGNED NOT NULL,
    exp INT NOT NULL DEFAULT 0,
    UNIQUE KEY uk_owner_room (owner_uid, room_id)
) ENGINE=InnoDB;

(owner_uid, room_id) 的组合不能重复，但两个字段单独重复是允许的。

INSERT INTO s_room_level_progress (owner_uid, room_id, exp)
VALUES (1001, 2001, 100)
ON DUPLICATE KEY UPDATE
    exp = 100;
  • 组合不存在：插入新记录。
  • 组合已存在：更新原记录的 exp。
  • 联合唯一索引只有两个字段，不影响插入三个或更多字段。

已有表添加联合唯一索引：

ALTER TABLE s_room_level_progress
ADD UNIQUE KEY uk_owner_room (owner_uid, room_id);

添加前需要确保不存在重复组合。

3. 常用写法

冲突时更新：

INSERT INTO s_room_level_progress (owner_uid, room_id, exp)
VALUES (1001, 2001, 1)
ON DUPLICATE KEY UPDATE exp = exp + 1;

只保证记录存在，不需要更新：

INSERT IGNORE INTO s_room_level_progress (owner_uid, room_id)
VALUES (1001, 2001);

注意：INSERT IGNORE 也可能将部分其他错误转为警告。

ON DUPLICATE KEY UPDATE 后面不能留空，必须有赋值表达式。

4. 性能与注意事项

  • 单条 SQL 完成插入或更新，通常比先查询再写入效率更高。
  • 大量并发更新同一条记录时，可能出现锁等待。
  • 多个唯一索引中的任意一个发生冲突，都可能触发更新。
  • 使用自增主键时，冲突更新也可能消耗自增 ID。

结论： 如果业务唯一标识是 (owner_uid, room_id)，应建立 UNIQUE KEY (owner_uid, room_id)，而不是普通联合索引。插入第三个字段 exp 不受影响。
