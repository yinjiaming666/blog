Flutter Build 和 Repaint 区别

2026-10-13 · 前端

1. Build 和 Repaint 是两个阶段

Flutter 渲染流程可以简单理解为：

build
  ↓
layout
  ↓
paint
  ↓
composite
  • build：根据当前状态重新生成 Widget 配置。
  • layout：计算组件大小和位置。
  • paint：把界面真正绘制出来。
  • composite：把不同 Layer 合成到屏幕上。

2. 子组件变化会不会导致父组件 rebuild？

通常不会。

如果子组件内部执行：

setState(() {
  count++;
});

一般只会让这个子组件对应的 Element 重新 build。

Parent
  └── Child  ← setState

结果：

Parent  不一定 rebuild
Child   rebuild

所以：

子组件 setState 不等于父组件也会 rebuild。

3. rebuild 之后一定会 repaint 吗？

不一定。

rebuild
   ↓
新的 Widget 配置
   ↓
更新 RenderObject
   ↓
属性真的变了吗？

可能出现：

属性没变化
→ 不需要 layout
→ 不需要 repaint

例如：

Container(
  width: 100,
  height: 100,
  color: Colors.red,
)

即使重新执行了 build()，如果这些属性都没有变化，底层不一定需要重新绘制。

所以：

rebuild ≠ repaint

4. 什么情况下会 repaint？

当影响视觉结果的属性发生变化时，RenderObject 可能会调用：

markNeedsPaint()

例如：

color: isSelected ? Colors.red : Colors.blue

颜色变化后：

rebuild
  ↓
color 发生变化
  ↓
markNeedsPaint
  ↓
repaint

5. 子组件 repaint 会不会影响父组件？

有可能。

如果没有独立的绘制边界：

A
└── B
    └── C  ← 需要 repaint

C 的 markNeedsPaint() 会向上寻找最近的绘制边界。

C
↑
B
↑
A
↑
最近的 RepaintBoundary

所以某个小区域变化时，可能导致一个更大的区域重新绘制。

注意：

这里说的是 repaint，不是 rebuild。

6. RepaintBoundary 是干什么的？

RepaintBoundary 用来隔离绘制区域。

RepaintBoundary(
  child: SomeWidget(),
)

可以理解成：

给这个组件单独一块画布。

例如：

Parent
  └── RepaintBoundary
        └── Child

当 Child 高频 repaint 时：

Child repaint
     ↓
RepaintBoundary
     ↓
到这里为止

可以避免 repaint 范围继续向外扩大。

7. RepaintBoundary 应该包裹谁？

最常见的是包：

  • 高频动画区域
  • 高频 CustomPainter
  • 频繁视觉变化的小区域
  • 绘制成本很高、但自身很少变化的静态区域

核心判断标准不是“动画还是静态”，而是：

这个区域的重绘频率是否和周围区域明显不同。

8. StatelessWidget 能代替 RepaintBoundary 吗？

不能。

StatelessWidget 表示：

这个 Widget 自己没有可变 State。

它主要属于 Widget / build 层。

RepaintBoundary 属于 RenderObject / paint 层。

两者解决的问题不同：

概念 主要解决的问题
StatelessWidget 组件自身没有 State
const 减少不必要的 Widget 更新
setState 触发对应区域 rebuild
RepaintBoundary 隔离 repaint 范围
markNeedsPaint 标记 RenderObject 需要重新绘制

9. 最重要的几个结论

1. build 和 paint 是不同阶段。

2. 子组件 setState，
   通常不会导致父组件 rebuild。

3. rebuild 不代表一定 repaint。

4. 子组件 repaint，
   可能让更大的绘制区域一起 repaint。

5. RepaintBoundary 的作用，
   是隔离 repaint，不是阻止 rebuild。

一句话记忆：

rebuild 是重新描述 UI，repaint 是重新画 UI，RepaintBoundary 是控制“重新画”的范围。
