记一次 MySQL 数据库死锁问题

2026-10-27 · 随笔

问题原因

s_member 表的主键 id 使用 VARCHAR(255) 类型存储，但在执行 SQL 时，查询条件传入的是数字：

SELECT id
FROM s_member
WHERE id = 33600134
    FOR UPDATE;

由于 id 是字符串类型，而 33600134 是数值类型，MySQL 会进行 隐式类型转换，导致主键索引无法正常用于精确查找。

在这种情况下，MySQL 可能执行全索引扫描或全表扫描。配合 FOR UPDATE 使用时，InnoDB 可能锁定大量甚至全部扫描记录，而不是仅锁定目标行，从而扩大锁范围，增加锁冲突和死锁的风险。

正确写法

SELECT id
FROM s_member
WHERE id = '33600134'
    FOR UPDATE;

确保查询参数与字段类型一致，使 MySQL 能够利用主键索引进行精确查找，避免不必要的大范围加锁。

总结

字段类型与查询参数类型不一致，不仅可能造成索引失效和性能下降，在 FOR UPDATE 等加锁场景下，还可能扩大锁范围，引发严重的锁竞争和死锁问题。

对于 VARCHAR 类型的主键，应始终使用字符串参数进行查询。
